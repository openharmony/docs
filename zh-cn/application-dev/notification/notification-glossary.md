## C

### Content Type；通知内容类型

用于指定通知的内容布局类型，决定了通知在通知中心中的展示样式。应用发布通知时，需根据展示需求选择对应的内容类型（如普通文本、长文本、多行文本、图片、实况窗等），并与对应类型的通知内容对象配合使用。

### Cross-device Collaboration；跨设备协同

将通知消息在手机、穿戴、平板、PC 等多设备形态间同步转发的机制，用于实现多设备通知共享。

### Customized Ringtone；自定义铃声

应用发布通知时指定的非默认音频提示资源，来源可为应用预置资源文件或沙箱内的音频文件。

## D

### Distributed Notification；分布式通知

借助分布式通信能力在多设备间协同同步的通知消息，使同一通知可在不同设备上呈现。开启后通知可在多台组网设备间流转，使用户在任意协同设备上都能查看和处理同一通知。

### Do Not Disturb Mode；免打扰模式

在设定时间段内抑制通知铃声、振动等提醒行为的模式，可按一次、每天或指定日期配置生效区间。用于避免通知在特定时段打扰用户，同时不丢失通知内容。

## G

### Geofence；地理围栏

以经纬度和半径定义的虚拟地理区域，作为通知的条件触发依据。当设备进入或退出围栏时触发预先配置的通知，适用于到站提醒、地点签到等基于位置的场景。

### Group Notification；组通知

将具有相同分组名称的多条通知聚合为一条成组展示的通知。折叠态下以概要形式呈现，展开后可查看各条通知详情，用于对同类通知归类整理、减少通知列表冗余。

## L

### Live View Notification；实况通知

一种支持实时更新内容的通知形式，可在通知中心持续展示动态变化的信息，适用于导航、打车、外卖等需要实时状态同步的场景。用于实时展示录音、录屏、音视频播放、通话、计时等长时任务进度，不持久化存储且生命周期与发布方一致。

### Local Notification；本地通知

由应用通过 Notification Kit 在客户端本地直接发布并展示的通知，发布后根据通知类型及场景产生对应的铃声、振动、横幅、锁屏、状态栏图标和通知中心显示。其生命周期与本地发布方一致，区别于跨设备同步的分布式通知。

## N

### Normal Live View；普通实况通知

由系统应用直接创建和更新的实况通知类型，支持增量、全量等多种更新方式以及附加图片、按钮等扩展内容，用于系统应用展示实时状态。

### Notification Action Button；通知操作按钮

通知中显示的交互式操作按钮，用于让用户通过点击按钮触发 WantAgent 动作。一条通知中最多包含两个按钮，适用于“回复”、“标记已读”等快捷操作场景。

### Notification Authorization；通知授权

应用发布通知前需获取的用户许可，由系统弹窗供用户决定是否允许应用发送通知。

### Notification Badge；通知角标

以数字形式展示在应用图标右上角的通知计数标识，用于向用户提示未读通知的数量，随通知的新增与查看动态增减。

### Notification Button；通知按钮

用于在实况窗中展示可交互的按钮，属于实况窗通知内容的组成部分。支持配置按钮名称列表和图标列表，最多支持 3 个按钮，与通知操作按钮的区别在于其专用于实况窗场景。

### Notification Capsule；通知胶囊

实况窗中以胶囊形态展示信息的组件，可承载标题、图标和背景色，用于在实况通知的有限区域内突出展示关键状态或摘要信息。

### Notification Card；通知卡片

通知发布后在设备上展示的卡片形式，展示在通知中心、状态栏等位置，供用户查看和交互。

### Notification Center；通知中心

设备上集中展示和管理通知的系统界面。通知发布后展示在通知中心，用户可在其中查看、管理和删除通知；应用可查询通知中心中本应用的存量通知数量和详情。

### Notification Check；通知校验

在通知发布前由系统应用对其内容与渠道进行鉴权的机制。校验通过方可展示，否则予以拦截，用于实现通知显示前的统一管控与过滤。

### Notification Content；通知内容

通知的内容结构，包括通知标题、正文等，提供多种通知类型的内容描述接口。应用根据展示需求（如普通文本、长文本、多行文本、图片、实况窗）选择对应的内容类型接口构造通知内容，普通文本通知内容是其他通知类型的基础结构。

### Notification Flags；通知标志位

用于按需削减通知提醒方式（如声音、振动、横幅、锁屏）的设置项。应用可据此关闭特定通知的某些提醒行为，实现比通知渠道更细粒度的提醒控制。

### Notification Kit；用户通知服务

为开发者提供本地通知发布通道的 Kit，可将应用产生的通知在客户端本地推送给用户，并根据通知类型及发布场景产生铃声、振动、横幅、锁屏、状态栏图标和通知中心等显示效果。

### Notification Progress；通知进度

用于在实况窗中展示进度条信息的描述字段，属于实况窗通知内容的组成部分。

### Notification Proxy；代理通知

由一个应用代表另一个应用发布的通知，发布时携带被代理应用的身份信息，使通知以被代理应用的身份展示。适用于系统应用代第三方应用统一发送通知的场景。

### Notification Request；通知请求

描述一条通知全部信息的数据载体，包含通知内容、标识、展示样式与交互行为等。发布通知时以此指定通知的各项属性，是通知发布与更新的基础。

### Notification Reminder Mode；通知提醒方式

通知到达时提醒用户的具体方式，包括铃声提示、锁屏、横幅、亮屏、振动、状态栏通知图标等。用于为指定应用或通知渠道配置具体的提醒行为，使不同通知以不同方式提醒用户。

### Notification Setting；通知设置

通知提醒方式开关的设置状态，包括锁屏通知、横幅通知、桌面角标、振动、铃声等开关状态，以及应用通知使能状态。用于查询或配置应用的通知提醒方式，可通过拉起通知设置界面供用户手动修改。

### Notification Slot；通知渠道

用于管理通知提示方式（声音、振动、锁屏显示等）的分类机制，同一渠道下的通知共享一致的提示行为。通过创建并配置渠道，可对同一应用不同类别通知的铃声、振动、横幅等提醒行为进行统一管理。

### Notification Smart Aggregation；智能聚合

依据聚合场景与规则将多条相关通知自动归并为一个聚合组的机制，可设置聚合组标题与摘要，用于对海量同类通知进行智能归并、提升通知列表可读性。

### Notification Snooze；稍后提醒

将已有通知设置为在指定时间间隔后再次提醒的机制，每次设置仅提醒一次，提醒方式与原通知相同，设置后原通知被删除。适用于用户希望延迟处理某条通知并在稍后再次收到提醒的场景。

### Notification Sorting；通知排序

提供有关活动通知的排序信息，包括通知渠道、通知级别和通知唯一标识。系统根据排序信息对已订阅通知中的活动通知进行排序展示，可通过通知排序映射表批量获取所有活动通知的排序信息。

### Notification Subscription；通知订阅

应用向通知子系统注册订阅者以接收通知变化的机制，支持订阅全部应用或指定应用发布的通知。

### Notification Update；通知更新

当新发布通知与已发布通知的 ID 和标签都相同时，新通知取代原有通知的更新机制。若不存在相同 ID 的通知则创建新通知，应用可通过设置 updateOnly 字段控制是否仅允许更新而不创建新通知。

## P

### Priority Notification；优先通知

通过优先级策略将特定类型通知标识为优先通知的功能，支持智能识别、用户关键词匹配、应用规则匹配等方式，涵盖优先级总开关、应用级开关、智能服务使能状态及优先策略等管理能力。用于确保重要通知（如缴费还款、动账提醒、物流进展、未接来电等）获得优先处理和展示，区别于通知渠道的通知优先级。

## S

### Silent Reminder；静默提醒

按应用维度的通知提醒方式，应用启用后其发布的通知在送达时不触发铃声和振动等提醒行为，仅静默展示。适用于不需要即时打扰用户的通知场景，独立于系统级的免打扰模式。

### System Live View；系统实况窗

由系统代理创建的实况窗通知，第三方应用无法直接创建，但可通过发布相同 ID 的通知更新其中指定内容，用于在受控前提下让三方应用复用系统实况窗能力。
